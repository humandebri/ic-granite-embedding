# Bekko a25m stable vocabulary: production implementation

2026-10-30, PocketIC 11.0.0, application subnet. This tests the ICP recipe-processed Wasm, not a mainnet deployment. A single disposable canister was installed with the prior release, populated with the pinned pack, activated, then upgraded to the new release without reuploading weights. The verified flag and byte count survived; the model was inactive until the controller reactivated it. Non-controller activation, upload and reset were rejected. Invalid input errors matched the prior release; reset invalidated the model and duplicate first-chunk retries were idempotent.

The model in this historical comparison validates the vocabulary descriptor and reads each requested F32 row from stable memory. The pack bytes and stable header do not change. A separate type keeps the existing heap-backed model API intact. `embedding_space` is unchanged; the tested `runtime_id` was `bekko25-runtime-2`. A subsequent bit-equivalent linear-weight optimization uses `bekko25-runtime-3`; see [the compact canister guide](../../docs/BEKKO25-COMPACT.md).

The measurements use `canister_status.memory_metrics`; they exclude other canister storage, snapshots and query-time temporary memory. In 416 comparisons, all embedding outputs matched bit-for-bit: 255 fixed-seed inputs covering lengths 2–256, 18 multilingual inputs, 40 Japanese inputs, one repeated-token input, and 102 repeated-token boundary inputs. A separate native test checked the old heap-backed API and verified that inserting whitespace into the pack metadata and relocating the data preserves the output.

Rows in the table are one fixed-seed input per length. All 416 inputs increased, by 5,897–1,584,128 instructions; the largest relative increase was about 0.0601%. The observed maximum was 4,805,042,704 instructions. Every case succeeded and stayed below the 4.9B release gate, but this sample does not establish a bound for all possible inputs or platform versions. A previous separate artifact/stress run observed 4,843,751,277 instructions and is not a measurement of this new Wasm.

One local activation took 2.31 s before and 0.18 s after; these single observations are not a latency or throughput guarantee. Query counters do not measure mainnet network latency, cold-memory effects, or concurrency. The external-row path reads up to 256 rows / 393,216 bytes per query, within the documented [1 GiB stable-memory read limit](https://docs.internetcomputer.org/references/resource-limits/).

The shared core was also checked with the a8m canister: 15 existing inputs were bit-identical before and after a real upgrade, with verified weights retained and reactivation required.

Build the current release using `scripts/build_bekko25.py` and `icp build bekko25 -e local`. Provide the previous and new Wasm paths and their expected SHA-256 hashes via `BEKKO25_BASELINE_WASM`, `BEKKO25_BASELINE_SHA256`, `BEKKO25_NEW_WASM` and `BEKKO25_NEW_SHA256`, plus `POCKET_IC_BIN`, then run `cargo run --release -p bekko25-bench --bin bekko25-stable-verify`. The runner requires the pinned pack and six-language cases in `.cache/bekko25/`, plus the Japanese input generated by [the memory study](../../experiments/bekko25-memory-study/README.md). It checks both fixture hashes before starting PocketIC, then rejects a failed query, unequal output, insufficient heap reduction, or a query at or above 4.9B instructions. Detailed output is local and ignored by Git.

Run `cargo run --release -p bekko25-bench --bin bekko25-stable-api-verify` for the resident/external/relocated-metadata API check. For a8m, supply the two artifacts and hashes through `BEKKO8_BASELINE_WASM`, `BEKKO8_BASELINE_SHA256`, `BEKKO8_NEW_WASM` and `BEKKO8_NEW_SHA256`, set `POCKET_IC_BIN`, and run `cargo run --release -p bekko25-bench --bin bekko-a8-regression`. Both local checks require their respective pinned packs.
